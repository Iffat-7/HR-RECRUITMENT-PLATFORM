# TalentGate V1.2 — Smoke Test Checklist

Run after `verify.sql` prints `VERIFY PASSED`. Work top to bottom. Tick boxes as you go.

**Prerequisites**
- [ ] `0001_foundation.sql`, `0002_recording_pipeline.sql` and `verify.sql` all executed successfully
- [ ] One HR user created and granted `HR` role (see `SUPABASE_DEPLOYMENT.md`)
- [ ] HR has created ≥ 1 **Position**, ≥ 3 **Questions** (one VIDEO, one AUDIO, one VIDEO_OR_AUDIO), one **Question set** containing them
- [ ] Test machine has a camera and microphone

---

## Candidate

- [ ] Register a new candidate (account + full registration in one flow; note the consent checkbox is mandatory)
- [ ] A `CND-XXXXXXXX` reference code is generated and shown (not a sequential number)
- [ ] CV upload: PDF accepted; `.exe`/`.zip` rejected with a clear message; > 10 MB rejected
- [ ] Profile photo upload (optional): JPEG/PNG/WebP accepted; thumbnail renders; replace works
- [ ] Log out, log back in — session persists, candidate record still attached
- [ ] Instructions page renders prep/retake rules
- [ ] Camera/microphone permission prompt appears; **deny** once → human-readable recovery message; **allow** → device checklist goes green
- [ ] Start interview is **blocked until the CV is on file** (server-enforced, not just UI)

## Recording

- [ ] VIDEO question: live preview → prep countdown (large, can't skip) → recording indicator + timer → auto-stop at max duration
- [ ] AUDIO question: mic-only (no camera prompt), level bars react to voice
- [ ] VIDEO_OR_AUDIO: candidate can pick either mode before devices open
- [ ] Preview plays back the exact take recorded (video player / audio player)
- [ ] Retake discards the local take (nothing uploaded) and shows attempts remaining
- [ ] Retake until limit → "Final attempt" label; RETAKE disabled after the limit (UI) — then confirm the server also rejects a tampered extra attempt (Security section)
- [ ] Upload shows real % progress; throttle the network (DevTools → Slow 3G) and confirm it still completes or fails cleanly
- [ ] Upload retry: kill Wi-Fi mid-upload → error with **Retry** → restore Wi-Fi → retry succeeds, no attempt consumed by the failure
- [ ] Refresh the page mid-interview → completed answers stay completed, progress rail correct, current question resumable
- [ ] Required question cannot be skipped; optional question (if configured) can be skipped
- [ ] Submit button stays locked until all required answers are uploaded; confirm modal warns it's final
- [ ] Completion page shows reference ID, position, submission date/time

## HR

- [ ] HR sign-in lands on `/admin` (a plain candidate hitting `/admin` sees the 403 page)
- [ ] Candidate list shows the new candidate with reference code + status `UNDER_REVIEW` after submission
- [ ] Candidate detail: dossier, masked CNIC, status history entries (`INTERVIEW`, `UNDER_REVIEW`)
- [ ] Recorded answers panel lists each question with attempt, type, duration, date, state
- [ ] Video playback works via **Play** (signed URL — check Network tab: `token=` parameter, no public bucket URL)
- [ ] Audio playback works
- [ ] Signed URL expires (~2 min) — replaying the old URL fails
- [ ] Submit an evaluation (category sliders come from the database, overall score, recommendation, notes)
- [ ] Change candidate status → history + audit log entries appear

## Security

- [ ] As candidate A, guess/forge another candidate's interview or question ID in the URL/console → `Not your interview question` / no data
- [ ] Candidate cannot call `prepare_recording` with a foreign `interview_question_id` (RPC raises)
- [ ] Anonymous request to `GET /storage/v1/object/interview-recordings/{any-path}` without auth → 401/403
- [ ] Candidate's signed-URL requests are scoped to their own folder only (storage policy uses folder 1 = own candidate id)
- [ ] Superseded takes remain listed for HR audit but playback defaults to the latest take
- [ ] A COMPLETED question cannot be ticked back to RECORDING via `update_interview_question_status` (raises "question is final")
- [ ] Audit log contains `interview.started`, `recording.prepared`, `recording.uploaded`, `interview.submitted`
